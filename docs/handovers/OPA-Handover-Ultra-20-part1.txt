**RULES CONFIRMED OR EARNED THIS SESSION:**

- **PIN THE WHOLE-FILE RESULT WITH A SHA-256, NOT JUST THE FRAGMENTS.** **This
  is the single most valuable rule learned this session.** In three separate
  replica cases (step 3 C8, step 5 C7, CI C8) **every fragment check passed -
  anchors found exactly once - and the source still differed from the reviewed
  file.** Only the whole-file result SHA caught it. Compute the SHA over the
  EOL-normalised planned OUTPUT; it is then independent of EOL, BOM and
  trailing-newline state, which are preserved separately.
- **BEHAVIOURAL INVARIANTS MUST RUN IN PHASE 1 *AND* PHASE 2.** Phase 1 on the
  planned array aborts before touching a tracked file; phase 2 on disk catches a
  corrupted write. **Driven by a replica case where a tampered installer wrote
  to a tracked file and only failed afterwards.**
- **SEMANTIC CHECKS SURVIVE A REGENERATED SHA; A SHA DOES NOT.** Every installer
  was replica-tested against a tampered CONTENT array with `EXPECT_SHA`
  regenerated to match. **The SHA passed every time.** What caught the tamper
  was the semantic assertion - required-set membership, `it.todo()` count,
  guard presence.
- **A DEPENDENCY GUARD MUST CHECK EXPORTED DECLARATION FORMS, NOT SYMBOL
  MENTIONS.** A decoy file with the four symbol names in a COMMENT plus one
  unrelated `export` passed the naive guard. Match `^export\s+function\s+NAME\s*\(`
  etc., anchored, **asserted by count**.
- **MEASURE EOL, BOM *AND TRAILING NEWLINE* FROM THE FILE ITSELF.** Trailing
  newline is a third independent property. **Two files in this repo lack it.**
- **AN OBSERVATION IS NOT A GATE.** Source line count is a NOTE; the result SHA
  is the gate.
- **VERIFY THE INSTALLER'S GUARDS AGAINST THE PUBLISHED ARTIFACT.** Extract the
  CONTENT array from the `.txt` about to be downloaded, hash it, compare to the
  embedded `EXPECT_SHA`. Self-consistency, not memory.
- Two phases; phase 2 must be able to fail (`written === plannedContent` catches
  a SAME-LENGTH substitution that a byte gate passes - **proven in all six**);
  create-only installers refuse to overwrite a divergent file; recovery
  instructions must match git state (`del` for untracked, `git checkout --` for
  tracked); idempotency tied to content and single-line (#103); assert by count
  (#42); one file, arrays of quoted strings; `node --check`; ASCII scan.

**TEST THE INSTALLER AGAINST A REPLICA BEFORE SHIPPING IT.** This session:
7, 11, 11, 12, 12 and 11 cases respectively. **Every revision re-runs ALL cases.**

#### `readiness-policy.ts` - 62 lines, NEW - THE POLICY LIVES HERE

```ts
export type ReadinessDependency = 'database' | 'redis';
export type RedisReadinessState = 'up' | 'down' | 'optional-down';
export type ReadinessVerdict = 'ok' | 'degraded';

export const REQUIRED_DEPENDENCIES = Object.freeze([
  'database',
] as const satisfies readonly ReadinessDependency[]);

const REQUIRED_DEPENDENCY_SET: ReadonlySet<ReadinessDependency> =
  new Set<ReadinessDependency>(REQUIRED_DEPENDENCIES);

export function dependencyState(dependency, reachable, required = REQUIRED_DEPENDENCY_SET): RedisReadinessState
export function readinessVerdict(reachability: Readonly<Record<ReadinessDependency, boolean>>, required = REQUIRED_DEPENDENCY_SET): ReadinessVerdict
```

**WHY `Object.freeze` ON A TUPLE RATHER THAN AN EXPORTED `ReadonlySet`:**
`ReadonlySet` is a COMPILE-TIME VIEW ONLY. The underlying `Set` stays mutable at
runtime, so an importer could cast it and call `.add('redis')` - **making policy
drift dynamically, which is exactly what ADR-016 D4 forbids.** The frozen tuple
is the exported policy; the Set is private. **`REQUIRED_DEPENDENCIES.push()`
throws at runtime - measured.** `readiness-policy.spec.ts` asserts
`Object.isFrozen(...)` for precisely this reason.

**TO GRADUATE REDIS (ADR-016 D5): add `'redis'` to that array. That is the
ENTIRE mechanism. There is no other place optionality is decided.**

## 6. Rejected - do not re-propose

All Ultra 19 rejections stand. **Additions from this session:**

- **A `ReadonlySet` as the EXPORTED policy value.** Compile-time only; the
  runtime Set stays mutable. Use a frozen tuple.
- **A generic `DependencyState` type shared by database and redis.** ADR-016
  widens ONLY Redis; a shared union invites widening `database` later.
- **A third `HealthService` constructor parameter for the required set.** Nest
  resolves by `design:paramtypes` and would try to inject a `Set` provider; a
  default value does not prevent that. It would need `@Optional() @Inject()` plus
  a module provider - real DI machinery for a policy that never varies.
- **A service-level test for D5's graduation.** There is no way to hand the
  service a different required set without adding the hook D4 rejects. **The
  policy-level test is stronger, not a compromise.**
- **A single-line 148-char Swagger summary**, and equally the 4-line wrapped
  form whose string line is still 125 chars. **`summary` + `description` is the
  answer** - max line 71, and it reads correctly in Swagger UI.
- **Naming Redis in the Swagger summary** (goes stale) or **citing ADR-016 in it**
  (internal architecture does not belong in a public API document).
- **Adding a trailing newline to `health.controller.ts` or the workflow.** An
  unrelated fix riding along in a scoped commit.
- **`--forceExit` on the CI jest run.** Issue 17.3 leaks a handle; masking it
  would hide the very thing that needs fixing.
