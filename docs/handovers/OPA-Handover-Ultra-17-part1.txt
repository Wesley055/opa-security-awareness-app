### Every command must carry its own control

**A command whose interesting result is a zero or an absence must also print a
number proving it reached real data.** `count=`, `files=`, `scanned=`, `lines=`,
`chars=`, `bytes=`. `probe=` before everything.

```powershell
"probe=unique-token"; <rest of command>
```

**This rule has now caught false negatives in five consecutive sessions.**

- `scanned=3157, hits=42` located every `OPA_ALLOW_MOCK_PROVIDERS` occurrence
  this session and sorted them into four classes - which is what made the rename
  scope knowable rather than guessed.
- `bytes=41845` vs `chars=41774` on `decision-log.md` proved the file contains
  ~24 real em-dashes and is CLEAN, not mojibake-damaged.
- **NEW: a probe that returns 0 because it could not possibly match looks
  identical to one that returns 0 because content is missing.** This session a
  verification searched for phrases that were line-wrapped in the target; both
  returned 0 and both were false negatives. **When a probe returns 0, ask whether
  the probe could have matched at all before believing the absence.**

**A sorted listing gives you a control for free.** Checking whether
`OPA_ALLOW_MOCK_PROVIDERS` exists in an alphabetical Azure settings list: seeing
`NODE_ENV` immediately followed by `REDIS_URL` PROVES absence. Look for the
boundary, not the absence.

### Paste damage, and how to recover

- **The first line gets dropped**, silently, often. Never anchor on line 1.
- **MORE THAN THE FIRST LINE CAN DROP.** This session an entire command's output
  above `handover_files=` was lost - roughly ten lines. **Do not assume only
  line 1 is at risk.**
- **The MIDDLE can drop.**
- **The console echo appears ABOVE the probe.** Not a dropped line.
- **A whole previous console block can be pasted back** and PowerShell tries to
  execute each line. **Happened this session with jest output** - `(6.677 s)` and
  `(7 ms)` parsed as expressions and threw a wall of ParserErrors. Harmless
  noise, nothing ran; read past it and re-issue the command.
- **A command can arrive pasted TWICE.** **Check HEAD, not the message.**

**The recovery that works: do NOT re-issue the same dump. Issue a NARROWER,
line-numbered read of exactly the missing facts**, with every line self-labelling
so a drop anywhere is detectable:

```powershell
$env:GIT_PAGER='cat'; cd C:\Projects\OPA; "probe=gitnarrow"; git log --oneline -3 | ForEach-Object { "log|$_" }; "status_sb=" + ((git status -sb) -join ' ~ '); "porcelain=" + @(git status --porcelain).Count
```

**Multi-window reads work and save round trips:**
```powershell
$p='docs\TODO.md'; "probe=x lines=$((Get-Content -LiteralPath $p).Count)"; $n=0; Get-Content -LiteralPath $p | ForEach-Object { $n++; if (($n -ge 10 -and $n -le 30) -or ($n -ge 100 -and $n -le 120)) { "$n|$_" } }
```

- **NO backslash escape.** `\"` ends the string early and hangs at `>>`. The

- **A TypeScript tagged template pasted into PowerShell is a syntax error.**

- **`[System.IO.File]` AND NODE IGNORE `cd`.** Trap #89. Absolute paths only.
- **`$LASTEXITCODE` IS STALE after a PowerShell-level failure.** Trap #88.

  reports `Select-String`'s status. **This is why the full-suite command is run
  unpiped and the `Tests:` line read directly.**
- **Square brackets in a path are WILDCARDS.** `-LiteralPath` is MANDATORY.

  **`decision-log.md` AND `incident-timeline.service.ts` both render mojibake in
  the console and BOTH ARE CLEAN.** **Do not "fix" either.**

- **Multi-paragraph commit messages use REPEATED `-m` FLAGS.** Used twice this

- **`curl` IS AN ALIAS FOR `Invoke-WebRequest`.** Use `curl.exe`. Trap #92.
- **`Measure-Object -Line` COUNTS NON-EMPTY LINES ONLY.** Trap #91. For a true
  count use `(Get-Content -LiteralPath $p).Count`.
- **`---` IN A PASTED-BACK CONSOLE BLOCK PARSES AS AN OPERATOR.** Trap #90. Use
  `=== thing ===`.
- **`Copy-Item` with a non-matching wildcard exits 0 and copies NOTHING.**
- **`Remove-Item -LiteralPath 'a','b'` CONTINUES past a missing path.** Trap #84.
- `Get-ChildItem | Where-Object` returns a bare object on one match, `$null` on

Rules:
- **Deliver as `.js`** - the chat viewer shows nothing for `.cjs`.
- **ONE file.** Arrays of quoted strings joined with `\n` - never template
  literals.
- **Two phases: plan every file, THEN write any.** Trap #52.
- **EVERY assertion that could make the edit unsafe belongs in PHASE 1.**
- **PHASE 2 MUST BE ABLE TO FAIL.** NEW REFINEMENT, and it was a real defect
  caught in review this session. A read-back that only PRINTS `FAIL` and exits 0
  lets a damaged write be committed. **Increment a counter and
  `process.exit(1)`.** The strongest single read-back check is
  `written === plannedContent`.
- **PIN CONTENT WITH A SHA-256 OF THE EOL-NORMALISED TEXT, NOT A BYTE COUNT.**
  NEW REFINEMENT. A byte count passes for any file of the same size; a
  same-length substitution defeats it. Normalising CRLF to LF before hashing
  makes the check survive a harmless line-ending conversion in transit, which
  matters with `core.autocrlf=true`.
- **USE ONE COUNTING METHOD THROUGHOUT.** NEW REFINEMENT. Counting an anchor with
  `indexOf` in phase 1 and a line-anchored regex in phase 2 measures two
  different properties; if they ever diverge, one phase passes on a definition
  the other does not use. **Exception, documented in the file: an idempotency
  guard should use the MORE sensitive substring check, so it aborts even on a
  mere mention.**
- **A gate should block the write only when violating it makes the edit UNSAFE.**
  Byte counts of the TARGET are observations, not gates. **Assert STRUCTURE.**
- **BE IDEMPOTENT, THREE-WAY, AND NEVER OVERWRITE A DIVERGENT VALUE.**
- **RECOVERY INSTRUCTIONS MUST COVER OWNED UNTRACKED FILES.**
- Assert by COUNT, not presence. Trap #42.
- **Every edit declares `anchorAfter`.** Trap #76.
- **Detect EOL per file. Detect and re-prepend the BOM. VERIFY both survived.**
  **Assert EOL UNIFORMITY (`crlf === lf_total`), not mere presence.**
- **PRINT the neighbour's measured EOL before writing a new file.**
- **Prefer INSERTS over REPLACES.**
- **State which directory it runs from and guard on a neighbour file.** Four
  roots: `apps/api`, `apps/website`, `apps/mobile-app`, REPO ROOT. Trap #65.
