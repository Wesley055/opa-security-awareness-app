### Paste damage, and how to recover

- **The first line gets dropped**, silently, often. Never anchor on line 1.
  Happened three times this session, including `files=3` and `cjs=`.
- **The MIDDLE can drop.**
- **The console echo appears ABOVE the probe.** Not a dropped line.
- **A whole previous console block can be pasted back** and PowerShell tries to
  execute each line. Happened once this session - an entire earlier output
  reappeared verbatim. Harmless noise; read past it.
- **A command can arrive pasted TWICE.** Its second run may report a benign
  failure - e.g. `git commit` saying "nothing to commit, working tree clean"
  after the first run committed. **Check HEAD, not the message.**

**The recovery that works: do NOT re-issue the same dump. Issue a NARROWER,
line-numbered read of exactly the missing facts.** Often the output already
contains the answer - a dropped `files=3` was confirmed by the three timestamps
that followed it.

```powershell
$p='path\to\file.ts'; "probe=read lines=$((Get-Content -LiteralPath $p).Count)"; $n=0; Get-Content -LiteralPath $p | ForEach-Object { $n++; if ($_ -match 'PATTERN|PATTERN2') { "$n|$_" } }
```

**Multi-window reads work and save round trips:**
```powershell
$p='docs\TODO.md'; "probe=x lines=$((Get-Content -LiteralPath $p).Count)"; $n=0; Get-Content -LiteralPath $p | ForEach-Object { $n++; if (($n -ge 10 -and $n -le 30) -or ($n -ge 100 -and $n -le 120)) { "$n|$_" } }
```

**`recordEvent` - the full mechanism, post-`96cf7de`:**

3. `findFirst` ordered by `sequence desc` for the tail.

## 7. Traps

#1-85 stand in Ultra 12/13/15. **#86-89 restated, all live.**

**#11 - A BADLY WRITTEN CONCURRENCY TEST PASSES WHETHER OR NOT THE LOCK EXISTS.**
Promoted here from `advisory-lock.int-spec.ts`'s own header because it is now
load-bearing twice. **The defence is a CONTROL CASE**: assert the contended
attempt has NOT completed while the lock is held, AND that a different key
completes immediately. Without the control you may be measuring connection
serialisation.

86. **A SCHEMA FIELD IS NOT A CAPABILITY** - `source: 'background'` and
    `Evidence.encryptionKeyId` both exist and neither is implemented. **A third
    candidate is live: `NotificationStatus.ACKNOWLEDGED`.** **Before claiming any
    capability, grep for the code that would write it, and print `scanned=`.**

    **NEW COROLLARY - THE INVERSE IS ALSO TRUE AND HAS NOW HAPPENED.** The
    timeline hash chain was fully implemented and recorded in two places as
    absent. **A capability recorded as missing is as expensive as a capability
    recorded as present. Read the mechanism before believing either.**

87. **`cd` PERSISTS BETWEEN COMMANDS AND SILENTLY REBASES RELATIVE PATHS.**
    **Prefix every read with `cd C:\Projects\OPA;`.**

88. **NEW - `$LASTEXITCODE` IS STALE AFTER A POWERSHELL-LEVEL FAILURE.**
    `$LASTEXITCODE` is set only by NATIVE commands. A missing executable, a
    cmdlet exception or a parse error leaves the PREVIOUS native command's code
    in place. **Observed: `az` not installed printed `exit=0`** - inherited from
    a `git push` several commands earlier. Sibling of #66, and worse, because #66
    gives a wrong-but-fresh value while this gives a RIGHT value from a DIFFERENT
    command. **For anything that might not exist, gate on
    `@(Get-Command name -ErrorAction SilentlyContinue).Count` instead.**

89. **NEW - `[System.IO.File]` AND NODE IGNORE `cd`; POWERSHELL CMDLETS HONOUR
    IT.** `Set-Location` does not update `[Environment]::CurrentDirectory`, so
    .NET static file APIs resolve relative paths against wherever the PROCESS
    started. **Observed: one command mixed `[System.IO.File]::ReadAllText('app.json')`
    with `Get-Content -LiteralPath 'app.json'`; the cmdlet read 33 lines
    correctly while .NET read an empty string, and every regex over it returned
    0.** The output was `lines=33` alongside `lf_total=0`, which is arithmetically
    impossible. **Always give `[System.IO.File]` an absolute path, and print
    `bytes=`/`chars=` as the control.** **Node has the same property** - an
    installer run from the wrong root reads empty rather than failing loudly,
    which is why every installer resolves from `process.cwd()` and prints it.
