### 3.1 THE COLLISION ADR-014 RECORDS AS OPEN - READ BEFORE 9c [M]

resolveForActivation takes the lifecycle advisory lock, then findFirst for a
session with status STARTED or ACTIVE ordered by startedAt DESC. IF ONE EXISTS
IT IS RETURNED UNCHANGED. Only when none exists is a new row created, with
startedAt defaulting to creation time. startSession surfaces both the resolved
startedAt and a `reused` flag.

THE COLLISION: a fix rejected as recorded-after-session-ended is told to
reacquire and resubmit. If the resolved session's startedAt is later than the
oldest buffered fix by more than START_GRACE_MS, that fix is then rejected as
PRECEDING the session and deleted. ADR-014's own recovery path walks its fixes
into ADR-014's own permanent rejection - in the airplane-mode scenario item 10
exists to demonstrate.

[D] ONE CONDITION, not two cases: does the oldest buffered fix clear
resolvedSession.startedAt - START_GRACE_MS. Session reuse makes that likely, not
certain. The grace absorbs WRITE LATENCY, not buffer duration.

[D] Because startSession returns startedAt, THE CLIENT CAN EVALUATE THIS BEFORE
RESUBMITTING rather than discovering it by rejection.

[D] The candidate fix - echoing an origin session so the server computes floor
from it - is recorded as CANDIDATE, NOT ACCEPTED. It introduces a second
client-supplied session reference, which is a TRUST MODEL change, and its
invariants are undecided.

[M] A SECOND CONSTRAINT ON ANY BYPASS: recordTrackedFixes derives the chain tail
via orderBy sequence DESC and appends. Admitting historical fixes into a session
already holding newer ones gives them HIGHER SEQUENCE with OLDER recordedAt -
the hash chain's order and time's order diverge. This reaches the tamper-evident
chain, not just the latest-fix query.

## 8. NEW TRAPS - ALL COST TIME THIS SESSION
================================================================================

TRAP #110 - Select-String HAS NO -Recurse. That is Get-ChildItem's parameter;
-Include filters a supplied path list rather than walking a tree. Use
`Get-ChildItem -Recurse -File | Select-String`.

TRAP #111 - A `>>` CONTINUATION PROMPT SWALLOWS PASTED TEXT AS SCRIPT. A pasted
error block was consumed by a console left mid-multiline, which choked on the
`+` markers and produced a wall of parser errors that looked like a new failure.
Same family as #104. CTRL+C to clear, then paste ONE line.

TRAP #112 - AN INSTALLER THAT NORMALISES LINE ENDINGS DESTROYS THE REVIEW GATE.
Reading with .replace(/\r\n/g,'\n') and writing LF rewrites every line of a CRLF
file, so `git diff` shows the WHOLE FILE changed instead of the insertion. Detect
EOL from the file, reuse it, and guard on mixed endings. The guard caught this
before any write.

TRAP #113 - Get-Content -Raw STRIPS THE TRAILING NEWLINE in PowerShell 5.1. An
edit that reads with -Raw and writes with WriteAllText silently removes it, and
the diff gains a phantom tail change. USE [System.IO.File]::ReadAllText when the
file will be written back.

TRAP #114 - POWERSHELL OPERATOR PRECEDENCE INSIDE A METHOD CALL. This:
    [System.IO.File]::WriteAllText($p, ($n.Replace($a,$b)) -replace "`n",$eol)
parses as THREE arguments and throws "Cannot find an overload... argument count
3". Worse, a following unconditional statement still printed "WROTE" - A FALSE
SUCCESS MESSAGE. Assign to a variable on its own line first, and report a
measured byte count rather than announcing success.

TRAP #115 - HERE-STRINGS DO NOT NEST, and JSX with backticks and ${...} cannot
survive a PowerShell double-quoted string. TWO WORKING ROUTES: hand-edit in an
editor and let `git diff` be the gate; or BASE64-ENCODE the payload, write it to
a .b64 file, decode it in Node, and print the decode for review BEFORE writing.
The second worked and is repeatable.

[M] NOTE ON sos.tsx LINE ENDINGS: the file was LF-ONLY before this session
(crlf=0, lf=421), unlike its neighbours. It was converted to CRLF during the
edit. If a future diff on that file looks unexpectedly large, this is why.

[R] THE METHOD THAT KEEPS WORKING: `git diff --stat` FIRST. "303 insertions,
zero deletions" was the single number that proved no line-ending rewrite before
a word of the body was read. Then `git diff -U5` read by a human. Then stage and
commit as SEPARATE steps - never in the same paste as the diff.
