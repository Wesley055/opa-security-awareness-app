### Every command must carry its own control

**A command whose interesting result is a zero or an absence must also print a
number proving it reached real data.** `count=`, `files=`, `scanned=`, `lines=`,
`chars=`, `bytes=`. `probe=` before everything.

```powershell
"probe=unique-token"; <rest of command>
```

**This rule has now caught false negatives in six consecutive sessions.**

- `scanned_ts=120, oldflag_hits=0` proved the flag rename was complete across
  `apps/api/src`. Without `scanned_ts` the zero would have been worthless.
- `pattern_hits=3, flag_hits=0` proved `emergency-intelligence.service.spec.ts`
  contains no flag reference - a TRUE zero, established by a probe that
  demonstrably found other content in the same file.
- **`amend_total=0` WAS A FALSE NEGATIVE THIS SESSION.** A regex searched for
  `Amendment|AMENDMENT`; the file's existing amendment at line 306 says
  **`**Amended 29 July 2026:**`** - the participle, not the noun. The absence
  was believed for one round trip and would have produced a second, divergent
  amendment style in the decision log. **Caught by re-probing with a broader
  pattern plus an unconditional control (`adr010_head=`).**

**A sorted listing gives you a control for free.** Checking whether
`OPA_BOOT_WITH_SUPPRESSED_MOCKS` exists in an alphabetical Azure settings list:
seeing it land between `NODE_ENV` and `REDIS_URL` PROVES presence. The same
adjacency proved its ABSENCE last session. Look for the boundary.

### Paste damage, and how to recover

- **The first line gets dropped**, silently, often. Never anchor on line 1.
- **MORE THAN THE FIRST LINE CAN DROP.**
- **The MIDDLE can drop.**
- **The console echo appears ABOVE the probe.** Not a dropped line.
- **A whole previous console block can be pasted back** and PowerShell tries to
  execute each line.
- **A COMMAND CAN ARRIVE PASTED TWICE, CONCATENATED.** **Happened this session**
  - a commit command arrived as `...Countcd C:\Projects\OPA; ...` and threw a
  ParserError. **Nothing ran, but that was VERIFIED by checking HEAD, not
  assumed from the error.** **Check HEAD, not the message.**
- **A trailing expression makes double-paste worse.** The commit that failed
  ended with a `"body_lines=..."` expression; the duplicate concatenated onto it.
  **Re-issued as the commit ALONE, with verification as a separate command, it
  worked first time.** **Put nothing after a long command.**

**The recovery that works: do NOT re-issue the same dump. Issue a NARROWER,
line-numbered read of exactly the missing facts**, with every line self-labelling
so a drop anywhere is detectable:

```powershell
$env:GIT_PAGER='cat'; cd C:\Projects\OPA; "probe=gitnarrow"; git log --oneline -3 | ForEach-Object { "log|$_" }; "status_sb=" + ((git status -sb) -join ' ~ '); "porcelain=" + @(git status --porcelain).Count
```

**Multi-window reads work and save round trips:**
```powershell
$p='docs\TODO.md'; "probe=x lines=$((Get-Content -LiteralPath $p).Count)"; $n=0; Get-Content -LiteralPath $p | ForEach-Object { $n++; if (($n -ge 10 -and $n -le 30) -or ($n -ge 100 -and $n -le 120)) { "$n|$_" } }
```
