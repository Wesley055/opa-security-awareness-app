### 2.1 THE CONTRACT AS BUILT [D]

  - Unknown session and another user's session return the SAME 404. The
    SERVICE returns one indistinguishable null for both, so no caller can
    accidentally split them. Never a 403. (ADR-009, ADR-014 section 2.)
  - IDEMPOTENT. An already-ENDED session returns alreadyEnded=true with NO
    write. The original endedAt and endedReason are preserved. A retry on a
    flaky connection is a success, not a 409.
  - endedAt comes from the DATABASE clock via
    SELECT date_trunc('milliseconds', now()), copying insertFixes exactly.
    NOT new Date(). endedAt is timestamp(3) and PostgreSQL ROUNDS on store,
    so an untruncated tail would be stored as a different millisecond.
  - status, endedAt and endedReason are ONE write. ADR-014 section 3.2 rules
    that a null endedAt on an ENDED session means reject-and-reacquire, so
    an ENDED row without endedAt must never exist, not even momentarily.
  - AN ATTACHED OPEN INCIDENT IS UNTOUCHED. Incident.status is not changed.
    Ending a journey is a telemetry event, not an incident outcome. ADR-008
    is explicit that "incident closed" and "still open" must never be
    conflated.

[D] endedReason on the wire is the ENUM, not the 'USER_ENDED' literal. On the
alreadyEnded path the stored reason is whatever ended the session, and once a
second owner exists that will not always be USER_ENDED. status IS the 'ENDED'
literal - it is invariant across owners. The asymmetry is deliberate.

[M] ENDING FREES THE USER. The partial unique index
journey_session_one_active_per_user covers WHERE status IN ('STARTED',
'ACTIVE') only - hand-added SQL at migration lines 90-94, invisible to
Prisma. So an ENDED session vacates the slot and the next activation creates
a new row. Pinned by an integration test. Without this, ending would change a
badge and nothing else.

## 3. THE RACE THAT SHIPPING THIS CREATED, AND CLOSED
================================================================================

[M] insertFixes reads session.status ONLY to decide the STARTED -> ACTIVE
promotion. IT DOES NOT REJECT ENDED. The ENDED rejection lives in
JourneyIngestionService.ingest, before insertFixes is reached.

THE RACE: ingest() read status outside any lock. A concurrent endSession
could commit ENDED between that read and the insert, and insertFixes would
append to an ended session on a verdict that was already stale.

[M] THIS RACE DID NOT EXIST BEFORE THIS COMMIT, because nothing wrote ENDED.
It was created by the endpoint and is therefore closed by it.

[D] THE FIX IS TWO HALVES, AND BOTH ARE REQUIRED:
  1. ingest() now takes the 2-arg session lock BEFORE its status read.
  2. endSession takes the 1-arg lifecycle lock THEN the 2-arg session lock.

A lock alone is not sufficient - without half 1, ingest still blocks (inside
insertFixes) and the stale verdict survives serialisation.

[M] LOCK ORDER IS LIFECYCLE-THEN-SESSION, and this MATCHES EXISTING CODE
rather than inventing a rule. recordRetriggerFix and the orchestrator both do
it. Verified by reading every public write path: recordActivationFix,
recordRetriggerFix and recordTrackedFixes all reach insertFixes as their LAST
call, and only recordRetriggerFix holds both - lifecycle first. NO PATH TAKES
SESSION-THEN-LIFECYCLE, so no cycle is reachable.

[M] COST: the session lock is now held for the whole ingest transaction
rather than only its write tail. Two concurrent ingests on the SAME session
serialise where they previously overlapped during DTO mapping. Different
sessions are unaffected.

    const sessionId =
