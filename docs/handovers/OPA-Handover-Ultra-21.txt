## 4. HOW TO REPRODUCE THE RENDER
================================================================================

PREREQUISITES, ALL VERIFIED THIS SESSION: [M]
- Docker running: opa-postgres and opa-redis (trap #27 - containers, NOT
  Windows services)
- API on port 3000:      cd apps/api;     npm run start:dev
- Website on port 3001:  cd apps/website; npm run dev
- A LIVE, UNREVOKED token for an incident

THE API MUST BE UP BEFORE THE PAGE LOADS. The Next server render calls
fetchTracking immediately. If the API is down you get UNAVAILABLE, which is the
page working correctly against a dead backend - a false negative that looks
like a page bug.

MINTING A TOKEN. There is NO HTTP endpoint that issues one. [M] Fifteen
controllers were swept; none issues a tracking token. Issuance happens only
inside the orchestrator's incident-creation transaction, which is the correct
posture for a capability token. To mint for an EXISTING incident, construct the
service directly:

  require('reflect-metadata');
  require('ts-node/register');
  const { PrismaService } = require('./src/prisma/prisma.service');
  const { IncidentAccessTokenService } =
    require('./src/modules/incident-access/incident-access-token.service');
  const prisma = new PrismaService();
  await prisma.$connect();
  const svc = new IncidentAccessTokenService(prisma);
  const { token, record } = await svc.issue(INCIDENT_ID);
  // print 'http://localhost:3001/i/' + token ON ITS OWN BARE LINE
  // then CTRL+CLICK it. Do not select it. Do not copy it.
  await prisma.$disconnect();

Save as .cjs in apps/api, run once, DELETE IT (trap #64).

[M] ts-node/register and reflect-metadata both resolve from the workspace root
node_modules, so TypeScript source runs directly and no dist freshness question
arises.

[D] Direct construction is preferred over NestFactory.createApplicationContext.
The latter boots schedulers, the dispatch worker, Redis and provider lifecycle
hooks for a task that needs one service and a Prisma client. Direct
construction also matches the project's own spec convention -
incident-access-token.service.spec.ts:24 does exactly this.

[M] PrismaService is a plain PrismaClient subclass with $connect on
onModuleInit and $disconnect on onModuleDestroy. No constructor arguments.

TOKEN FACTS WORTH KNOWING BEFORE MINTING: [M]
- issue(incidentId, scope?, tx?) - only incidentId is required. Scope defaults
  to FAMILY_BEARER.
- INITIAL_VALIDITY_MS = 6 hours. ABSOLUTE_LIFETIME_MS = 7 days, set AT
  ISSUANCE, so a fresh token on an old incident gets a full ceiling.
- issue() does NOT revoke prior tokens. It only creates.
- The raw token is returned ONCE and never persisted. Only the SHA-256 hash is
  stored (ADR-008). Lost means re-issued; it cannot be recovered.
