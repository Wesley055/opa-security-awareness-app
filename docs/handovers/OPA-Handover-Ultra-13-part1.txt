## 1. Working method

You have no file access. Manual command-and-paste: one command, the user runs
it in PowerShell, pastes raw output back. One thing at a time. Never assume
file state - verify it.

**A parallel session with file access has existed at least once.** If two
sessions run at once, only ONE may write to the repo or the handover parts.
Establish which at the start. A shared mutable artifact with two writers and no
lock is how a good diff gets reverted.

### Every command must carry its own control

**A command whose interesting result is a zero or an absence must also print a
number proving the command reached real data.** `count=` before a dump.
`files=` before a listing. `probe=` before everything.

```powershell
"probe=whatever-this-command-is"; <rest of command>
```

**The probe catches a stale re-paste. It does NOT catch a wrong artifact.**
Trap #72. Decision rule for a paste whose first line is not the expected probe:
- Plausible *continuation*, contiguous and complete -> the read was fine, the
  paste dropped line 1. Say so, continue.
- A *previous* probe -> stale re-paste. Disregard, re-issue.
- An unrelated artifact -> wrong paste. Say so, re-issue.

**The console echo of the command often appears ABOVE the probe.** That is the
echo, not a dropped line. Distinguish them.

**A paste can drop the MIDDLE, not just line 1.** Observed this session: a
`git diff` came back missing its `--numstat` header and its first two hunks
while later hunks were intact. **The recovery that worked: do not re-issue the
same dump. Issue a NARROWER, line-numbered read of exactly the missing facts.**

### The first line of a paste gets dropped

Always the first line, always silently.
- **Never anchor an installer on the first line of a file.**
- Numbered output makes it detectable:
```powershell
$p='path\to\file.ts'; "probe=read count=$((Get-Content -LiteralPath $p).Count)"; $n=0; Get-Content -LiteralPath $p | ForEach-Object { $n++; "$n|$_" }
```

**The filtered variant is better when you only need a few identifiers:**
```powershell
$p='apps\mobile-app\src\services\journey-tracker.ts'; "probe=decl lines=$((Get-Content -LiteralPath $p).Count)"; $n=0; Get-Content -LiteralPath $p | ForEach-Object { $n++; if ($_ -match 'PATTERN|PATTERN2') { "$n|$_" } }
```
Short enough to survive truncation, and `lines=` proves it reached the file.
**This is the read that settled the whole diagnosis this session.**

**The same pattern re-derives a structural index.** Use it instead of trusting
recorded line numbers:
```powershell
$p='docs\architecture\decision-log.md'; "probe=adr-order"; $n=0; Get-Content -LiteralPath $p | ForEach-Object { $n++; if ($_ -match '^## ADR-') { "$n|$_" } }
```

### PowerShell specifics

- **NO backslash escape.** `\"` terminates the string early and hangs the shell
  at `>>`. The escape is a BACKTICK. Ctrl+C recovers. Trap #56.
- **PowerShell STRIPS double quotes from native-command arguments.** Trap #78.
- **Square brackets in a path are WILDCARDS.** `-LiteralPath` is MANDATORY.
- **`Get-Content` misreads UTF-8 as ANSI.** Keep every installer anchor
  ASCII-only. Trap #63. **Seen live this session:** `decision-log.md`'s
  ADR-001..008 headings render as `ADR-008 a<...> Incident tracking links`.
  **Those are REAL em-dashes and the file is genuinely clean.** The mojibake is
  in the console, not the file. **Do not "fix" it.** ADR-009/010/011 show a
  plain hyphen because they deliberately use ASCII.
- **`-Encoding utf8` on WRITE adds a BOM.** All writing goes through Node.
- **A multi-paragraph commit message uses REPEATED `-m` FLAGS.** Never embed
  newlines in one quoted `-m` - PS 5.1 hangs at `>>`. Used four times this
  session, up to six paragraphs, no issue.
- `2>&1 |` on a native command is unsafe.
- **A pipeline masks the real exit code.** Check unpiped. Trap #66.
- **NEVER pipe two object shapes into one stream** - the second prints as
  nothing, silently, exit 0.
- `Get-ChildItem | Where-Object` returns a bare object on one match, `$null` on
  none. Wrap in `@()`.
- `$matches` is automatic. Never use it as a name.
- `git status --short` cannot show an ahead-count. Use `git status -sb`.
- Set `$env:GIT_PAGER = 'cat'` at session start.
- **`Copy-Item` with a non-matching wildcard exits 0 and copies NOTHING.**
  Always print `files=` from the source enumeration BEFORE copying.
- **`Remove-Item` on a missing path is a non-terminating ERROR that does not
  stop the rest of a `;`-chained line.** Seen this session: a delete failed,
  and the `git commit` after it still ran and correctly reported nothing to
  commit. Read the whole output, not just the last line.
- Keep commands short. Compound `if`/`else` with nested quoting WILL hang 5.1.

## 7. Traps

Traps #1-79 stand, in Ultra 12 and unchanged. Load-bearing ones restated in
section 1. **Three are new.**

80. **A FAST REFRESH PRESERVES MODULE STATE, SO IT TESTS THE OLD CODE WHILE
    LOOKING LIKE IT TESTS THE NEW.** `journey-tracker.ts` is a module-scope
    singleton. Over a fast refresh, `running` stays true, `startTracking()`
    early-returns, the new code never executes, and the SURVIVING subscription
    keeps whatever options it was created with. **Cost: an entire session
    concluded that two correct fixes had regressed the sender and recommended
    in three places that they not be committed.** **Fully close and reopen Expo
    Go for every tracker test.** Counter-check: `POST /journey/sessions` in the
    API log - present means a full start ran, absent means it did not.
    **General form: when new code appears to have made things worse, prove it
    RAN before concluding it is wrong.**

81. **`receivedAt` IS NOT UNIQUE AND THE ENVELOPE ORDERS BY IT WITH NO
    TIE-BREAK.** `insertFixes` captures `date_trunc('milliseconds', now())`
    ONCE per call, so every fix in a batch shares one `receivedAt`. The
    envelope selects the newest fix by `receivedAt desc` alone, so with a
    multi-fix batch the database may return EITHER row. Harmless at 2 fixes
    (10 s of staleness). **Under 9c a 200-fix buffered batch shares one
    `receivedAt`, so an arbitrary tie-break could surface the fix from the
    START of an outage as "latest"** - defect 1 resurrected at a much larger
    scale. **Fix: `ORDER BY receivedAt DESC, sequence DESC`. Before 9c.**

82. **A 201 FROM THE ORCHESTRATOR IS NOT PROOF NOTIFICATIONS WERE SENT, AND
    `contactsNotified` IS COMPUTED BEFORE THEY EXIST.** Dispatch runs through
    the outbox worker asynchronously. Observed: activate returned 201 at
    18:57:59.978, the worker dispatched 4 notifications at 18:58:02, and **the
    SOS screen displayed "0 contacts" throughout.** Not merely stale -
    structurally unavailable at response time. **On a panic screen, telling the
    user nobody was alerted while alerts are going out is the worst possible
    direction for the error.** Part 2 section 9b.6.
