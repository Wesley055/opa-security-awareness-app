### Every command must carry its own control

**A command whose interesting result is a zero or an absence must also print a
number proving it reached real data.** `count=`, `files=`, `scanned=`, `lines=`,
`chars=`, `bytes=`. `probe=` before everything.

```powershell
"probe=unique-token"; <rest of command>
```

**This rule has now caught false negatives in seven consecutive sessions.**

This session:
- **`hits=0` WAS A FALSE NEGATIVE AND WOULD HAVE ANSWERED q47 BACKWARDS.** A
  Redis consumer sweep returned zero. Re-probed case-insensitively with an
  unconditional control: `redis_ci_hits=38, import_control_hits=484`. Had the
  zero been believed, the session would have concluded nothing depends on Redis
  and closed the question wrong.
- `scanned_ts=120` proved the sweep reached the tree, and `control_await_hits=18`
  did the same for the orchestrator scan.
- `control_D=6` proved a grep for six ADR decision points read real content, so
  three companion zero-checks were trustworthy.
- Seven provider files each printed their own `lines=`, so `hits=0` in all seven
  was a true zero rather than a dead pattern.

**A CONTROL MUST BE UNCONDITIONAL.** The pattern that works is: search for the
thing, AND search for something that MUST be there, and print both.

### Paste damage, and how to recover

- **The first line gets dropped**, silently, often. Never anchor on line 1.
- **MORE THAN THE FIRST LINE CAN DROP.** **The MIDDLE can drop.**
- **THE TAIL CAN DROP.** **Happened this session** - a 209-line spec arrived
  complete to line 120 and stopped. **Recovery: re-read from a line BEFORE the
  cut so the overlap can be checked.** Reading from 118 when the cut was at 120
  proved the drop was clean rather than worse than it looked.
- **The console echo appears ABOVE the probe.** Not a dropped line.
- **A whole previous console block can be pasted back.**
- **A COMMAND CAN ARRIVE PASTED TWICE, CONCATENATED.** **Happened again this
  session**: `git cat-file -t 44ff065 cd C:\Projects\OPA; "probe=place"...` -
  two commands fused. **The byte gate caught it** (`files=0` -> "do not run").
  Trap #100.
- **Put nothing after a long command. Verify in a SEPARATE command.**

**The recovery that works: do NOT re-issue the same dump. Issue a NARROWER,
line-numbered read of exactly the missing facts**, with every line self-labelling.

```powershell
$env:GIT_PAGER='cat'; cd C:\Projects\OPA; "probe=gitnarrow"; git log --oneline -3 | ForEach-Object { "log|$_" }; "status_sb=" + ((git status -sb) -join ' ~ '); "porcelain=" + @(git status --porcelain).Count
```

**Multi-window reads work and save round trips:**
```powershell
$p='docs\TODO.md'; "probe=x lines=$((Get-Content -LiteralPath $p).Count)"; $n=0; Get-Content -LiteralPath $p | ForEach-Object { $n++; if (($n -ge 10 -and $n -le 30) -or ($n -ge 100 -and $n -le 120)) { "$n|$_" } }
```

- **D1.** Liveness and readiness stay separate. `/health` = is the process

  `REDIS_REQUIRED=false`**, which is named and rejected in the ADR.
- **D5.** Graduation is **atomic**: Redis becomes readiness-critical only in the
  same change set that deploys a capability depending on it, including
  provisioning, configuration, failure-path tests, readiness update, and
  operational verification.
- **D6.** The Azure probe path is **pinned to `/health`**, recorded in three
  places: the ADR, `TODO.md`'s deployment section, and **a permanent
